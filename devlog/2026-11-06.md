## 性能：highlight.js 按需引入

### 需求

聊天页全量引入 highlight.js（190+ 种语言，约 1MB），实际问答只用常用语言。
10-23 / 10-30 遗留项。

### 实现

- `ChatMessage.vue` 改为 `import hljs from 'highlight.js/lib/common'`
  （官方 37 种常用语言，含 JS / TS / Python / Java / Go / Rust / SQL / Bash 等）
- Markdown 渲染与高亮函数不变；未注册的冷门语言回退为纯文本代码块

### 验证

- esbuild 单独打包对比：全量 1,080,478 B（gzip 313,702 B）
  → common 161,654 B（gzip 53,332 B），约减少 85%
- 构建产物中高亮相关 chunk 304KB
- headless Chrome + mock SSE 返回 JS / Python 代码块：
  两种 `pre code.language-*` 均渲染，关键字与字符串都有 `hljs-*` 着色
- `npm run build` 通过

## 性能：Twikoo 滚动懒加载

### 需求

首页 `Guestbook` 挂载即加载 Twikoo（约 900KB），留言板在首屏以下。
10-23 / 10-30 遗留项。

### 实现

- `IntersectionObserver` + `rootMargin: 300px`：滚动到留言板附近才
  `import('twikoo')` 并初始化；之前不下载 Twikoo chunk
- 不支持 IntersectionObserver 的浏览器回退为立即加载
- 模板保留静态 `#twikoo-container`，Twikoo 用选择器 `el: '#twikoo-container'`
  挂载（与原生产代码一致）
- 占位「评论加载中...」是静态兄弟节点，只用原生 `hidden` 属性切换，
  不用 `v-if`/响应式状态 —— 否则 Vue 会 patch 到 Twikoo 接管的节点，
  触发 `insertBefore` NotFoundError
- `onNuxtReady` 后再挂 observer；init 后轮询 `.twikoo` / `.tk-submit`，
  确认真正渲染才隐藏占位；超时显示「留言板加载失败，请刷新重试」

### 验证

- headless Chrome（CDP + 本机 Chrome）：
  - 首页初始 Twikoo 相关请求 **0 个**
  - 滚动到留言板后出现 **1 个** `twikoo.js` chunk 请求，
    `.tk-submit` 提交框正常渲染
  - 无 Vue DOM patch 报错（只剩无关的 `ws://localhost:4000` 连接失败日志）
- `npm run build` 通过

### 上线后补充：阻止 Nuxt 预取

- 首版上线后发现：Nuxt 会把页面内所有 dynamic import 以
  `<link rel="prefetch">` 预取（vue-bundle-renderer 生成），
  线上 HTML 里仍有 Twikoo chunk 的 prefetch 链接 —— 等于空闲时照样下载 1MB
- 修复：`nuxt.config.ts` 增加 `build:manifest` 钩子，把 manifest 中
  `name` 含 `twikoo` 的条目 `prefetch` / `preload` 置为 `false`，
  保留运行时 `import('twikoo')`
- 重建后 manifest：`{"name":"twikoo.all.min","prefetch":false,"preload":false,...}`

### 线上慢网络排查：init 静默结束但 DOM 为空

- 线上用 CDP 探针复现：observer 触发、占位/容器挂载、Twikoo chunk 加载完成、
  `init` 返回，但卡片里没有任何 Twikoo 节点，评论接口也没请求
- 先怀疑版本差异：线上实际打包 Twikoo **1.7.24**，本地 node_modules 是 **1.7.11**
  （lockfile 写的是 1.7.11，Vercel 构建缓存装成了 1.7.24）。本地换成 1.7.24
  重新构建后仍能正常渲染 → 排除版本因素
- 最终改为更保守的挂载方式：静态 `#twikoo-container` + 选择器挂载 +
  `onNuxtReady`，占位节点只用原生 `hidden` 切换，不参与 Vue patch；
  `init` 后用 `waitForRender` 确认 `.twikoo` / `.tk-submit` 出现才隐藏占位
- 本地生产构建（node-server + Twikoo 1.7.24）复验：滚动后 UI 正常渲染，
  API 走到 `/api/twikoo`（本地后端不可达返回 502，但 UI 正常）

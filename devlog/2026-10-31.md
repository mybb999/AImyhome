# 2026-10-31

## 角色卡对话「生成失败 + 刷新丢内容」根因修复

### 现象

用户报告两个问题(同一根因):

1. 角色卡模型发消息报错「生成失败」
2. 刷新页面后,刚聊的内容没了

### 排查(服务器日志 + 数据库实证)

日志两次记录(会话 24,两个不同模型都失败):

```
角色卡模型生成失败(model=x-apex-xl-1022-16k, conversation=24)
langgraph.errors.InvalidUpdateError: Ambiguous update, specify as_node
  File ".../main.py", line 532, in gen
    await memory.aupdate_state(config, {"messages": [...]})
```

- **生成本身是成功的**:答案已流式返回给前端,失败发生在「写回记忆」这一步
- 两个模型、同一会话都失败 → 是**会话级**问题,不是模型问题
- 查 PG:会话 24 的 checkpoint `versions_seen` 是 `{"__start__": {}}`(空)——
  之前一次豆包对话的图运行在 `__start__` 处被打断,只留下了这个「残废」checkpoint
- LangGraph 的 `aupdate_state` 不带 `as_node` 时,要靠 `versions_seen`
  推断消息该归属哪个节点;推断不出就抛 Ambiguous → 写回失败 → 这轮
  什么都没存 → 刷新后自然看不到
- 同类隐患:压缩过的线程(compress 写的 checkpoint `versions_seen` 也是空)
  角色卡写回一样会踩

### 修复

不用 `aupdate_state`,改成和「压缩上下文」同款写法 —— 读旧消息 →
删线程 → `aput` 整包重写(旧消息 + 本轮问答)。版本从头计,
与节点归属推断彻底脱钩,任何 checkpoint 形状都能写。

- Agent 服务:`app/main.py` 新增 `write_card_turn`;`stream_card_chat` 写回改用
  它;`AgentGraph` 暴露 `checkpointer` 属性
- 回归测试 `tests/test_card_memory.py`(3 个):毒 checkpoint 追加、
  新线程首轮、连续两轮递增

### 验证

- 本地用和生产同形状的「毒 checkpoint」复现了 `InvalidUpdateError`,
  修复后正常追加(测试锁死)
- 全套 155 个测试通过

### 备注

- 修复前失败的轮次没有落库,无法找回;后续轮次恢复正常保存
- 会话 24 里残留的那条「被打断的未回答消息」会继续显示在历史里,可用「清空对话」清掉

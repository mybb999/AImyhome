## 博客接口缓存 + 首页按需取数

### 问题

用户反馈「点击导航就卡」。线上实测（TTFB）：

| 地址 | TTFB | 响应大小 |
|---|---|---|
| `/` | 0.95s | 151KB |
| `/blog` | 0.88s | 181KB |
| `/blog/css-ju-zhong-fang-fa` | 1.03s | 59KB |
| `/api/blog` | 0.78s | 87KB |

两个根因：

1. `/api/blog` 没有任何缓存，每次导航都在服务端把 204 篇文章全量查一遍
2. 首页只为显示 6 篇卡片，却请求并内联了全部 204 篇的元数据（87KB JSON → 151KB HTML）

### 改动

- `nuxt.config.ts`：新增 `routeRules`，`/api/blog` 与 `/api/collections` 走 `swr: 300`（CDN 缓存 5 分钟）
- `server/api/blog.ts`：支持 `limit` / `offset`，响应结构改为 `{ items, total }`
- `types/blog.ts`：新增 `BlogListResponse`
- `pages/index.vue`：改为 `GET /api/blog?limit=6`，总篇数取接口返回的 `total`
- `pages/blog/index.vue`、`pages/blog/collection/[slug].vue`：适配新响应结构
- `components/shared/BlogList.vue`：`hasMore` 在有 `moreLink` 时按 `total > posts.length` 判断，避免只取 6 篇时不显示「查看全部」

### 效果（本地实测）

| 指标 | 改动前 | 改动后 |
|---|---|---|
| 首页 HTML | 110KB | **26.8KB** |
| `/api/blog` 响应（首页用） | 87KB / 0.78s | **3.4KB** |
| 首页卡片数 | 6 | 6（不变） |
| 列表页 | 24 张 / 204 总数 | 24 张 / 204 总数（不变） |

线上 CDN 缓存生效后，`/api/blog` 的 TTFB 预计从约 0.78s 降到几十毫秒。

## 文章页返回按钮：文案统一 + 回到原位置

### 改动

- 侧栏与正文底部的返回按钮统一为「← 返回博客列表」
- 新增 `composables/useBlogOrigin.ts`：用 sessionStorage 记录来源路径、滚动位置、已渲染卡片数（10 分钟过期）
- 点文章卡片时记录；文章页按钮指向记录的来源（无记录回退 `/blog`）
- 列表页数据就绪后恢复卡片数量与滚动位置，恢复后清除记录

### 踩坑

1. **Nuxt 路由切换会滚回顶部**，覆盖刚恢复的位置 → 在 2 秒内持续校正，用户一滚动就放弃
2. **全局 CSS 的 `scroll-behavior: smooth`** 会让每次校正都重新开始动画，永远停不到目标 → 必须显式 `behavior: 'instant'`
3. 测试时也要禁用平滑滚动，否则读到的是动画中间值

### 验证（Playwright + Edge 148）

- `/blog` 加载更多到 72 张、滚到 2000px → 进文章 → 返回：位置 2000、卡片 72 张 ✅
- `/blog/collection/vue` 滚到 900px → 进文章 → 返回：回到该文集、位置 900 ✅
- 直接打开文章 URL → 返回链接回退 `/blog` ✅

## 线上 Bug：文集页显示全部文章

### 现象

点任意文集（如 Vue），列表里混入了所有文集的文章；实测 `/api/blog?collection=vue` 返回 204 篇而不是 37 篇。

### 排查过程

| 检查 | 结果 |
|---|---|
| 本地 dev 调 `?collection=vue` | ✅ 正常返回 37 篇 |
| 线上加随机参数绕过缓存 | ❌ 仍返回全部 204 篇 |
| 线上 `?id=<slug>` | ❌ 返回的也是 204 篇列表（`id` 分支代码完全不同） |
| 线上 `/api/blog/?id=<slug>`（多一个斜杠，不同路径） | ✅ 正确返回单篇 |

`?id=` 和 `?collection=` 同时失效，说明请求根本没按查询参数区分——问题不在业务代码，在缓存层。

### 根因

**Vercel 的 ISR（`routeRules` 里的 `swr`）只按路径名缓存，完全忽略查询字符串。** 所有 `/api/blog?...` 变体共享同一份缓存，第一次请求（全量列表）把后续所有变体都污染了。

本地 dev 不走 ISR，所以完全测不出来。

### 修复

- 移除 `/api/blog` 的 `swr`（该接口依赖 `collection` / `id` / `limit` 查询参数）
- `/api/collections` 没有查询参数，保留 5 分钟缓存
- 首页「只取 6 篇」的收益不受影响（`limit` 重新生效）

### 教训

- **带查询参数的接口不能直接套用 Vercel ISR**。要缓存只能把变体编码进路径（如 `/api/blog/collection/[slug]`）
- 涉及平台缓存/边缘行为的功能，本地验证通过不等于线上正确，必须部署后实测

## 线上 Bug：文章代码块与正文平铺

### 现象

文章详情页的代码块没有独立的背景/边框/间距，看起来和正文混在一起；标题层级也不明显。

### 排查

| 检查 | 结果 |
|---|---|
| 渲染出的 HTML 是否有 `<pre><code>` | ✅ 有，结构和转义都正常 |
| 编译后的 CSS 是否包含 `.prose` 规则 | ❌ 完全没有 |
| `package.json` 是否装了 `@tailwindcss/typography` | ❌ 没装 |
| `tailwind.config.ts` 的 `plugins` | ❌ 空数组 |

### 根因

`BlogContent.vue` 里写了一大串 `prose prose-invert prose-pre:bg-surface-lowest ...`，但项目**从未安装 `@tailwindcss/typography`**，这些类名全部无效。Tailwind 的 preflight 又把 `pre` / `h2` / `p` 的默认边距清零，于是代码块和正文糊成一片。

### 修复

- 安装 `@tailwindcss/typography@0.5.20`
- `tailwind.config.ts` 注册插件：`plugins: [typography]`

这一下会把所有 Markdown 排版一起恢复：代码块背景/圆角、标题层级、段落间距、列表、引用、图片圆角等。

### 教训

- 用 `prose-*` 类名前先确认插件已安装；类名无效不会报错，只会静默失效
- 之前 5 篇示例文章几乎没代码块，所以这个缺陷一直没暴露

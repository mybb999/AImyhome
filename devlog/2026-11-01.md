# 2026-11-01

## 角色卡开场白:新会话第一条消息是角色的开场白

### 需求

选了角色卡、会话空白时,用户发出第一句话后,对话框里要把卡的开场白
作为第一条 AI 消息显示 —— 和 DZMM 自己的对话框一致,不然一上来只有
问答,角色设定对用户来说很突兀。

### 实现

- **Agent 服务**:`app/main.py` 新增 `build_card_saved_messages` ——
  空白历史 + 选了卡 → 写回记忆的消息以开场白打头(开场白 → 用户问题 →
  AI 回答);已有历史的会话不加。刷新后开场白仍在(和后续对话存同一份记忆)
- **博客**:`ChatPanel.vue` 发送时,dzmm 模型 + 已选卡 + 消息区为空 →
  先推一条 assistant 气泡(开场白),再推用户消息,最后才是流式占位

### 验证

- 后端 3 个新测试(空白历史加开场白 / 有历史不加 / 没卡或开场白为空不加),
  全套 158 个通过
- headless Chrome + 本地 mock:选卡发送后,气泡顺序 =
  开场白 → 用户问题 → 流式回答

## 角色卡回答:重新生成 + 版本切换

### 需求

生成的回答右下角加 🔄 重新生成;生成过的每个版本服务器存档,
◀ x/N ▶ 左右切换浏览,显示总条数和当前第几条。

### 范围(已确认)

只角色卡模型;只有最后一条回答可重生(记忆是线性的,重生旧对话会
打乱后续上下文);版本跨刷新保存。

### 实现

- **Agent 服务**
  - 新表 `chat_versions`(user_id / conversation_id / version_no / content),
    会话当前轮生成过的每个版本;新一轮开始或清空对话时重置
  - `POST /api/agent` 加 `regenerate: true`:`trim_last_answer` 切掉记忆里
    最后一条 AI 回答(用户消息不重复追加)→ 同卡重新生成 → 新回答写回
    记忆并作为下一版本存档
  - `GET /api/conversations/{id}/versions` 返回当前轮所有版本
- **博客**
  - `ChatMessage.vue`:最后一条回答右下角 🔄 + `◀ x/N ▶`(多于 1 个版本
    才显示箭头);浏览历史版本纯展示(记忆里始终是最新版)
  - `ChatPanel.vue`:send() 的流式部分抽成 `streamAgent()` 供
    send/regenerate 共用;重生失败恢复旧回答(不能把上一条吞了);
    出错的气泡不显示重生按钮
  - Nitro 转发 `server/api/agent/conversations/[id]/versions.get.ts`

### 验证

- 后端 7 个新测试(trim_last_answer 4 个 + 版本接口鉴权/404/返回 3 个),
  全套 165 个通过
- headless Chrome + 本地 mock:首版无箭头 → 🔄 重生 → 出现 2/2 →
  ◀ 切到 1/2 且正文变回首版 → ▶ 切回 2/2

### 线上反馈:重生没箭头 + 按钮太小

- 用户说「重生成功了但没有版本箭头」;排查结论:
  - 后端日志**没有任何 regenerate 请求进来**,且会话 26 记忆里最后一条
    回答和 v1 存档内容逐字一致 → 重生在数据层面从未发生
  - 查线上 bundle:重生逻辑完整部署(点击→emit→regenerate:!0 都在);
    本地 mock 全流程通过;存档/重置函数在真实 PG 上逐条复现正常
    (v1→v2→reset→v3 全对)→ 后端代码没问题
  - 推断:点击没真正发出请求(按钮太小点不中/点到边缘)
- 修复:按钮改成带边框胶囊「🔄 重新生成」;◀ x/N ▶ 加大成 8×8 点击区
  胶囊;**1/1 也显示**(让用户能看出「版本已拉取,还没重生过」)
- 待用户复测;若重生后仍无箭头,看 DevTools Network 里
  POST /api/agent 是否发出

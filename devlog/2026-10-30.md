## 侧栏「剩余积分」接真实数据

### 需求

侧栏用户卡原来写死「剩余积分 100」，是占位值。新需求：显示**当前所选大模型账户的真实剩余额度**（不是给用户记账，不做扣减）。

### 数据源

| 模型 | 来源 | 展示 |
|---|---|---|
| 豆包 | 火山引擎费用中心 `QueryBalanceAcct`（只读） | `剩余积分 910（≈ ¥0.91）` |
| 智谱 | GLM-4.7-Flash 免费 | `剩余积分 免费` |

换算：1 积分 = 0.001 元。服务端缓存 5 分钟；查不到显示「—」，不影响聊天。

### 实现

- **Agent 服务**：新增 `app/credits.py`（AK/SK + SigV4 签名调火山开放接口，不引入官方 SDK）+ `GET /api/credits`
- **博客**：新增 `server/api/credits.get.ts` 薄壳转发；`ChatPanel.vue` 侧栏接真实值，随模型切换变化
- **配置**：`.env` 新增 `VOLC_ACCESS_KEY` / `VOLC_SECRET_KEY`（火山控制台「访问控制」生成，注意不是推理用的 `DOUBAO_API_KEY`）

### 踩坑

1. **签名一直 `SignatureDoesNotMatch`**：火山引擎签名密钥派生是 `HMAC(sk, date)` 起步，不能像 AWS 那样先拼 `"AWS4"` 前缀 —— 我照 AWS 习惯加了 `"VOLC"`，错得隐蔽。最后拿官方 SDK 对同一请求打对照，发现签名串一致、只有最终签名不同，才定位到密钥派生
2. **没有用官方 SDK**：`volcengine` 包带 20 来个依赖，为一个只读余额接口不值得；手写签名 + 官方 SDK 生成的测试向量锁死（单测里固定时间戳和假密钥，签名必须逐字节一致）
3. **智谱没有余额接口**：控制台登录态的内部接口，API key 调 404；好在 Flash 免费，直接显示「免费」

### 验证

- 后端真实调用：`{ok: true, points: 910, balance_cny: 0.91, currency: CNY}`
- 浏览器（headless Chrome + localStorage 模拟登录）：豆包显示 `剩余积分 910（≈ ¥0.91）`，智谱显示 `剩余积分 免费`
- 131 个后端测试全绿

## 角色卡模型接入（Card-Chat API v2，仅 lucas）

### 需求

给 lucas 账号增加一组「角色卡模型」：模型列表是动态拉取的（49 个），请求必须带角色卡设定；卡片可以选择或新建。

### 实现

- **Agent 服务**：`app/dzmm.py`（模型列表缓存 10 分钟 + 流式对话）、`role_cards` 表（字段与接口 card 对象一致）、`GET/POST /api/role-cards`、`GET /api/card-models`
- **聊天路由**：前端选 `dzmm:<模型id>`，后端按前缀走纯聊天路径（实测 tools 不生效），但复用现有 checkpointer —— 多轮对话、侧栏历史都能接上
- **权限**：列表和聊天接口都校验登录用户名 == `lucas`，其他账号 403；前端只是把入口藏起来
- **UI**：模型下拉 →「角色卡模型」→ 先选角色卡（胶囊，可新建）→ 再选模型；新建弹窗填写名字/背景/性格/场景/开场白/系统提示

### 验证

- 真实接口：模型列表 49 个；流式回答正常
- headless Chrome：级联展开、卡片胶囊、新建弹窗保存后自动选中新卡
- 144 个后端测试全绿

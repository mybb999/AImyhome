## 侧栏「剩余积分」接真实数据

### 需求

侧栏用户卡原来写死「剩余积分 100」，是占位值。新需求：显示**当前所选大模型账户的真实剩余额度**（不是给用户记账，不做扣减）。

### 数据源

| 模型 | 来源 | 展示 |
|---|---|---|
| 豆包 | 火山引擎费用中心 `QueryBalanceAcct`（只读） | `剩余积分 910（≈ ¥0.91）` |
| 智谱 | GLM-4.7-Flash 免费 | `剩余积分 免费` |

换算：1 积分 = 0.001 元。服务端缓存 5 分钟；查不到显示「—」，不影响聊天。

### 实现

- **Agent 服务**：新增 `app/credits.py`（AK/SK + SigV4 签名调火山开放接口，不引入官方 SDK）+ `GET /api/credits`
- **博客**：新增 `server/api/credits.get.ts` 薄壳转发；`ChatPanel.vue` 侧栏接真实值，随模型切换变化
- **配置**：`.env` 新增 `VOLC_ACCESS_KEY` / `VOLC_SECRET_KEY`（火山控制台「访问控制」生成，注意不是推理用的 `DOUBAO_API_KEY`）

### 踩坑

1. **签名一直 `SignatureDoesNotMatch`**：火山引擎签名密钥派生是 `HMAC(sk, date)` 起步，不能像 AWS 那样先拼 `"AWS4"` 前缀 —— 我照 AWS 习惯加了 `"VOLC"`，错得隐蔽。最后拿官方 SDK 对同一请求打对照，发现签名串一致、只有最终签名不同，才定位到密钥派生
2. **没有用官方 SDK**：`volcengine` 包带 20 来个依赖，为一个只读余额接口不值得；手写签名 + 官方 SDK 生成的测试向量锁死（单测里固定时间戳和假密钥，签名必须逐字节一致）
3. **智谱没有余额接口**：控制台登录态的内部接口，API key 调 404；好在 Flash 免费，直接显示「免费」

### 验证

- 后端真实调用：`{ok: true, points: 910, balance_cny: 0.91, currency: CNY}`
- 浏览器（headless Chrome + localStorage 模拟登录）：豆包显示 `剩余积分 910（≈ ¥0.91）`，智谱显示 `剩余积分 免费`
- 131 个后端测试全绿

## 角色卡模型接入（Card-Chat API v2，仅 lucas）

### 需求

给 lucas 账号增加一组「角色卡模型」：模型列表是动态拉取的（49 个），请求必须带角色卡设定；卡片可以选择或新建。

### 实现

- **Agent 服务**：`app/dzmm.py`（模型列表缓存 10 分钟 + 流式对话）、`role_cards` 表（字段与接口 card 对象一致）、`GET/POST /api/role-cards`、`GET /api/card-models`
- **聊天路由**：前端选 `dzmm:<模型id>`，后端按前缀走纯聊天路径（实测 tools 不生效），但复用现有 checkpointer —— 多轮对话、侧栏历史都能接上
- **权限**：列表和聊天接口都校验登录用户名 == `lucas`，其他账号 403；前端只是把入口藏起来
- **UI**：模型下拉 →「角色卡模型」→ 先选角色卡（胶囊，可新建）→ 再选模型；新建弹窗填写名字/背景/性格/场景/开场白/系统提示

### 验证

- 真实接口：模型列表 49 个；流式回答正常
- headless Chrome：级联展开、卡片胶囊、新建弹窗保存后自动选中新卡
- 144 个后端测试全绿

### 追加修复（当天）

1. **线上发消息 500**：`AgentGraph` 封装只透传了流式方法，角色卡路径调 `aget_state` 直接 AttributeError。补 `aget_state` / `aupdate_state`，并用真实 PG checkpointer 验证「写入→读回→删除」全链路。
2. **角色卡可查看/编辑**：点击卡片胶囊打开预填弹窗，PUT 保存；顶栏显示「模型 · 当前卡名」。
3. **模型可用性**：接口不返回状态，全量实测 49 个模型，2 个稳定 500；后端内置已知不可用 + 运行期失败缓存（429 短标记 / 5xx 长标记），前端灰显并标注原因。
4. **卡片必填项**：接口实测 `description` 和 `first_message` 必填、消息须以 assistant 开场 —— 创建/编辑时校验，发送时兜底补开场白。
5. **模型信息展示**：模型列表显示积分消耗（接口 `pricing`，积分/千 tokens）和上下文长度；响应时间接口不返回，改为**真实对话时实测**首字/总耗时并缓存展示。
6. **「适合类型/剧情」说明**：DZMM 接口没有该字段，改从 Ivôrune 的 tRPC 接口 `chat.models` 拉取（49 个模型按 `internalName` 一一对应，含分类/推荐/会员等级）。该站点只允许服务器访问（本地 TLS 被重置），后端缓存 1 小时、失败只丢说明；列表同时展示「推荐」「Lv.X」。实测 3 个模型稳定 500，已内置不可用。
7. **生成失败排查增强**：流内异常原来只发给前端、服务端不留痕 —— 补 `logger.exception`（含模型/会话 id），DZMM 非 200 也记录状态码与错误体；已知不可用模型在发送前直接拦下并提示「该模型当前不可用:原因」；博客转发优先透传 Agent 的 `detail` 文案，前端不再显示整段 JSON。

## 聊天卡顿优化

### 排查

服务器本身不慢：负载 0，Agent 直连接口 1ms。慢在两端：

| 测量 | 冷 | 热 |
|---|---|---|
| 首页 `/` | 4.9s | 0.5~0.7s |
| `/api/credits`（Vercel 函数 → 国内源站） | 1.7~3.1s | 0.5s |
| `/api/agent/models` | 0.76s | 0.26s |

1. Vercel 冷启动 + 跨境回源（不是代码问题）
2. **聊天时前端每个 token 都 `+=` 内容并滚动，触发整篇 `md.render` + highlight.js 高亮** —— 长回答越聊越卡（10-23 devlog 里就记过这个待办）

### 改动

- token 攒批：60ms 合并一次再写响应式状态，滚动跟着批次走
- 生成中**纯文本直出**，流结束后一次性渲染 Markdown + 代码高亮（不再每 token 渲染）
- `/api/credits`、`/api/agent/models` 加 `Cache-Control` 边缘缓存（60s / 300s），减少 Vercel 函数调用

### 验证

- mock SSE：生成过程中是纯文本（无 `.prose`），结束后 `<strong>`、列表均正确渲染
- 剩余待办：highlight.js 全量引入 1074KB（按需引入）、Twikoo 913KB（滚动到留言板再加载）
